# :bar_chart: gh-widgets
### GitHub stat SVGs that render on a timer, not on every page load

`github-readme-stats` and the services like it render on *request* — someone opens your README, and a box somewhere calls the GitHub API with your token. gh-widgets inverts that: a systemd timer renders plain SVG files to disk, and nginx serves them as files. No runtime API calls, no JS, no third party holding a token, no rate limit tied to how many people look at your profile.

## :globe_with_meridians: They're live right now
**https://nitjsefni.eu/widgets/** — `stats.svg` · `streak.svg` · `languages.svg` · `external.svg` · `impact.svg`

Real files off my own account, regenerated hourly. Hotlink one into a README and it just works — it's an image.

## :bullseye: impact.svg — share, not volume
Contribution graphs reward noise. `impact.svg` asks a harder question: *of the work in this repo, how much is mine?* Three ranked tables — Pull Requests, Issues, and **Live Code** — each scored `WilsonLowerBound(mine/total, z) * mine^gamma`, so a 1-of-1 repo can't outrank a sustained relationship.

Live Code means what it says: the renderer `git clone`s each candidate repo (full history — blame needs it), runs a blame pass, counts the lines still surviving under my authorship, and deletes the clone. Current top row: **2,749 of 11.3k lines in `envaar/vaar` — 24.3%**. Top PR row: 24 of 64 in `warior456/Sculk-Depths`, 37.5%.

## :bug: The parts that were actually hard
:warning: **Line ownership has to be an exact match.** GitHub gives you two noreply forms (`login@users.noreply.github.com` and `id+login@users.noreply.github.com`); a substring test on either one over-counts silently. It's a set-membership check on the derived addresses now — and if you commit from an address that isn't a noreply, you must declare it, or those lines stop counting as yours *as a smaller number, never an error*.

:warning: **A full-year contribution query gets you `RESOURCE_LIMITS_EXCEEDED`.** Cold cache walks 12 sequential monthly windows instead; a warm one refetches only the trailing 7 days and merges.

:warning: **PRs opened and merged between two renders never entered the cache at all** — a real data-loss bug that produced a completely plausible-looking widget for weeks. Fixed by a bounded single-page MERGED sweep each run.

:gear: The three Python files ship as a matched set: each renderer asserts the shared module's `COMMON_VERSION` at startup and hard-exits on mismatch, so a half-finished `cp` produces a renderer that refuses to run rather than one that quietly renders from a stale module.

:shield: Fail-soft by design — a corrupt or schema-mismatched cache falls back to a full fetch; a failed live fetch with a good cache renders from cache and shows you the cache timestamp instead of breaking the image.

## :tools: Stack
Python **3.9+**, **standard library only** — no `requirements.txt`, no `pyproject.toml`, nothing to install. GraphQL for everything. `render-impact.py` is the one exception: it shells out to `git` and `git-fame` for the blame pass.

## :zap: Follow-up: why "live code" is expensive, and how it stays cheap

Counting *surviving* lines is the only honest way to measure code impact — added-lines counters reward a big commit that someone deleted the next week. But it means blaming whole repositories, which is not something you can do on a timer without thinking about it.

What keeps it affordable:

```
candidate set     only repos where a PR of mine actually merged
clone depth       full history (blame is wrong without it)
re-blame trigger  default-branch HEAD oid changed since last count
otherwise         reuse the cached line count, clone nothing
disk              clone → blame → delete, one repo at a time
schedule          twice daily (05:30 / 17:30 UTC), after the hourly pair
```

So a normal run blames nothing at all — it checks HEAD oids and reuses counts. Only a repo that actually moved pays for a clone, and only `--resync` re-blames everything at once.

```
cache.json          252 KB   366 calendar days, 1,098 PRs
impact-cache.json   264 KB   PRs, issues, totals, per-repo line counts
```

Two caches, deliberately separate — pointing both renderers at one file was a mistake I made once and would rather nobody repeat.
