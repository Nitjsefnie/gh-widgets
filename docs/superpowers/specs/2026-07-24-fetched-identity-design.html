Design spec · gh-widgets

Fetched identity, env-driven knobs, shared helpers

Context render-impact.py hardcodes the facts that decide whose impact it measures — a literal set of org names and a literal email matched by substring — while render.py derives the same concept from the API. The two scripts also carry a large block of byte-identical duplicated code. This spec replaces the constants with fetched identity, moves the metric knobs to the environment, and extracts the duplication into one shared module.

Decision
Identity is derived from the token's own account; configuration may only add to it.
  1. Identity is fetched, not configured. Env vars may only add to the derived set, never replace it.
  2. The four metric knobs become env-driven, with the current values as defaults.
  3. The duplication moves to ghwidgets_common.py, loaded by path, with a version constant both scripts assert against.
  4. install.sh copies all three files, so a partial copy stops being possible.
Why not simply move the constants into env vars: a new org would still count as external until someone edits a unit file. That is the same failure in a different location, not a fix.
01

Background

What the reader needs to know to evaluate the rest.

The impact renderer decides which repositories are external by comparing a repo owner against a hardcoded INSIDERS set, and decides which lines are ours by testing whether a commit-author email contains the substring "nitjsefnie". Both are constants in source.

The substring test is the weaker of the two: in a third-party repository, commit author email is attacker-controllable, so any address containing that substring is counted as ours. The impact is cosmetic — an inflated line count — but the check is wrong in kind, not just in degree.

02

Before vs. after

The behaviour being replaced, against what takes its place.

Before
  • Org names hardcoded in INSIDERS; joining another org silently counts it as external.
  • Ownership decided by "nitjsefnie" in email — a substring test on untrusted input.
  • Z and three gammas fixed in source, citing a validation script that is not in the repo.
  • A large block of code duplicated across two scripts, drifting independently.
After
  • Insiders derived from user.organizations + login; new orgs are picked up automatically.
  • Ownership decided by exact membership in a derived address set.
  • Knobs read from the environment, current values as defaults, unparseable input exits non-zero.
  • One shared module, version-asserted at startup.
03

Verified facts

Everything below was confirmed by query against the live account, not assumed.

FactValueHow verified
databaseId present GraphQL query against the live account
Constructed noreply {databaseId}+{login}@users.noreply.github.com Matches the address recorded in /root/CLAUDE.md
Fetched org list matches the current INSIDERS literal GraphQL against the live account
user.email not fetchable Production token lacks read:user; requesting the field fails the entire query with INSUFFICIENT_SCOPES

Row three is the load-bearing one: the fetched set reproduces the hardcoded set, so this refactor changes no rendered number today. Row four constrains the design — email must not appear in the query at all.

04

Identity model

Two derived sets, both additive-only from configuration.

insiders = casefold({login} ∪ fetched_orgs ∪ split(GH_EXTRA_INSIDERS))

our_emails = lower(
    {f"{databaseId}+{login}@users.noreply.github.com",   # modern noreply
     f"{login}@users.noreply.github.com"}                # legacy noreply
    ∪ split(GH_EXTRA_EMAILS)
)

Matching is exact set membership, replacing the substring test. The box address moves from a source constant to GH_EXTRA_EMAILS in the unit files.

A repo is external iff it is public and its owner's login (casefolded) is not in insiders — one predicate, shared by both scripts.

05

Environment variables

Defaults preserve today's behaviour exactly.

VariableDefaultMeaning
GH_EXTRA_INSIDERS—Comma-separated extra owner logins treated as insiders. Additive.
GH_EXTRA_EMAILS—Comma-separated extra addresses counted as ours in the blame pass. Additive.
IMPACT_Z2.58Wilson lower-bound z score.
IMPACT_PR_GAMMA1.0Volume exponent, PR table.
IMPACT_ISSUE_GAMMA1.75Volume exponent, issue table.
IMPACT_LOC_GAMMA0.5Volume exponent, live-code table.

Unparseable numeric values exit non-zero. Silently falling back to the default would render wrong numbers with no signal — the exact failure mode this spec exists to remove.

07

Module boundary

Only what both scripts genuinely share moves.

The shared module holds the theme table and FONT; gql() with its retry contract; PR_QUERY, fetch_pull_requests() and fetch_issues(); load_cache() / save_cache(); fmt_short(), xml_escape(), base_card() and stamp_cache_notice(); plus the new identity functions.

Card rendering, the metric math, and the blame pass stay in their own scripts.

Both scripts load the module by explicit path relative to their own __file__ via importlib.util.spec_from_file_location — the pattern already used by test_render.py. No sys.path mutation, no packaging, no build step. Deployment renames render.py to render-gh-widgets.py, so import-by-name would break; import-by-path does not care about the script's own filename.

08

Verification

How the implementer confirms the change is correct.

python3 -m unittest discover -v passes.
render.py imports nothing outside the stdlib. Grep its imports.
Live run reproduces the previous tables. The fetched insider set equals the old literal, so the SVG must not change.
Corrupt COMMON_VERSION deliberately. Both scripts must refuse to start.

Out of scope

Named so the reader knows these were considered, not missed.

The max_pages=50 truncation interacting with the "absent ⇒ merged" inference
Real but latent, repaired weekly by --resync, and unrelated to constants. Tracked separately.
Retuning Z or the gammas
They become configurable; their values do not change.
Vendoring impact_stats.py / clone_fame.py
The validation scripts the knob comment cites live only in an ephemeral scratchpad. Worth recovering into the repo, but that is its own change.
